# CPU baseline: first CI execution (2026-11-05)

**Status:** exploratory smoke benchmark, **not controlled research evidence**. The benchmark and compiler validation passed.

- [CI run](https://github.com/arman-dogru/deep-goose/actions/runs/42052914398)
- [Raw artifact (JSON, metadata, report)](https://github.com/arman-dogru/deep-goose/actions/runs/42052914398/artifacts/13427278467)
- Goose: v2026.3, compiled through Clang 18.1.3.
- C: GCC 13.3.0 via \`cc -O2\`. **Different compilers:** not a clean language performance comparison.
- Python: 3.12.3, NumPy 2.5.4, OpenBLAS threads limited to one.
- GitHub-hosted Ubuntu 24.04 x86-64 virtualized runner with two visible CPUs. No dedicated hardware/clock control.
- Three independent process executions per implementation/case.
- 105 timed samples, nine workload configurations, zero execution failures and zero aggregate-checksum failures.
- PyTorch was not installed in this run.

## Interpretation / limitations

1. **Do not claim Goose is faster than C for add/ReLU based on this table.** The C side used GCC while Goose compiled to C through Clang; generated C may vectorize or be aliased differently. A rerun with Clang on both sides is required.
2. Goose and C are comparable for sequential \`f32\` dot in this particular setup (~63 µs); both are much slower than the optimized NumPy vectorized reduction.
3. The naive \`i,j,k\` matrix multiplication performs poorly relative to optimized NumPy BLAS. This is an algorithm/kernel optimization issue as much as a language issue. It is **not** evidence that Goose cannot perform optimized GEMM.
4. Tiny timings, few trials, shared hosted hardware and unusual outliers make the first run unsuitable for publication-grade speedup claims.
5. Input initialization, process startup, warmup and output checksum occur outside the timed loop. Pure Python computes with binary64 values; compiled kernels and NumPy use \`f32\`.
6. Aggregate checksums are smoke checks only: they may miss errors that cancel in the sum. Add elementwise tests and numerical gradient checks before training.
